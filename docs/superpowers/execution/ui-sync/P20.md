# P20 — Complete current OpenDesign screen audit

The earlier P00–P18 acceptance covered 15 requested templates, not the complete OpenDesign project. P19 added Home; Holland remained outside the new UI boundary. This audit explicitly examines all 23 active HTML templates (17 student/auth/public, six admin), their 24 mapped runtime pages, and the welcome/question plus forgot/OTP/reset states. `index.html` duplicates Home; two archive_experiments files are not active screens. `/admin/holland-content` is an extra runtime screen.

Fresh browser audit: 23 test cases passed against production preview, capturing 24 runtime page states at 390×844, 768×1024 and 1440×900. Recovery is reached through real UI handoffs, not persisted credentials. Source captures use the same viewport sizes and prototype motion is frozen in the browser. Original design files are unchanged. This proves route/render coverage, not pixel parity or backend integration.

## Required visual corrections

- P21: Holland welcome, carousel, current-question UI, actual group counts and live draft radar. Preserve boolean payload/draft/unknown-outcome handling.
- P22: Profile summary with real counts, latest normalized result and target/goal, while preserving existing editors/avatar flow.
- P23: Replace result-only links with actual owned result mini radars in recommendation/detail/roadmap sidebars.
- P24: Place actual goal/analytics summaries in Dashboard source-style banner and metric cards.

Admin screens are present and operational, but they are adaptations rather than exact reproductions. Their differences above are explicitly not labelled as full visual parity. The six prototypes contain simulated numbers, charts, weights, logs and unsupported mutations; this audit does not fabricate endpoints/data to make the images equal. Existing unavailable states and role/owner guards remain.

Artifacts: `.superpowers/ui-sync/P20/reference/` and `current/` (72 runtime screenshots; 69 base source captures plus question/reset states). Structured mapping and source hashes: [P20-screen-map.json](P20-screen-map.json). New `tests/e2e/ui-design-coverage.spec.ts` keeps all mapped screens in future regression runs.

The initial harness run used two inaccurate page titles and an unqualified h1 locator that also matched loading headings; corrected the selectors to actual titled ready states. The fresh 23/23 result is after those harness fixes. No application correction was hidden in this audit.

Scope: fixture/browser + manual source/runtime image review. No live backend, seed, scoring, dependency, push or deploy changes. The feature branch and original History stash are preserved.
